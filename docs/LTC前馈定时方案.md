# LTC 前馈定时解码方案：调研、算法设计与实测

> 调研日期：2026-10-06。基准脚本已固化在仓库 `docs/ltc-compare/`（`bench-ff.mjs` /
> `bench-ff-wronglock.mjs` / `ff-decoder.mjs`），算法规格书与对比协议见
> `docs/ltc-compare/README.md`——与其他算法对比时以该 README 为准。
> 全部数据来自本机合成信号（LTC + 可控干扰），48 kHz / 25 fps / PCM16 / 6 秒。
> 前一阶段调研见 `docs/LTC识别强化方案.md`（开源盘点、PLL 原型、P0–P4 路线）。本文是其"下一步收益点——前馈定时"的落地。

## 0. 结论先行

1. **开源界没有可搬用的更先进 LTC 算法**（二十年来事实标准 libltc 是逐采样 AGC + 连续时钟跟踪）；**学术界有现成理论可直接迁移**：Oerder–Meyr 前馈定时（平方律谱线）、Gardner 定时误差检测、RFID 领域 FM0/Miller 的最大似然序列检测。没有值得投入的神经网络路线。
2. 按通信理论重做的**分段前馈定时解调器**已实现并测完：识别矩阵 **16/16 通过、零错锁、零误锁**；白噪门限从 0.15 推到 **0.20（−7.3 dB，+2.5 dB）**，对白门限 0.80（−23.7 dB）与 PLL 原型持平且**全程零错锁**；工频堆叠/带限/软削波/±0.4% 变速/1 秒信号丢失全部正确。
3. 本方案最大的增益点恰好是文档预言的"白噪声场景"：定时估计**完全不使用边沿判决**，宽带噪声制造的伪跳变不再进入环路。
4. 开发过程中抓到并修掉三个会导致系统性错读的真实 bug（半比特相位模糊、小时 digit 单帧软判决、"低支持小簇"放行），细节见 §4——这些经验教训直接适用于后续把 P2 集成进 `src/`。

## 1. SOTA 调研：外部世界有什么

### 1.1 开源实现（上一轮已盘点，结论不变）

libltc 仍是事实标准，核心是**逐采样 min/max 衰减跟踪（AGC）+ 施密特触发 + 半比特计数 + 连续时钟跟踪**。它的优势不在"聪明"，在时钟从不让判决参与。LTC 专用解码器无神经网络开源实现。

### 1.2 通信理论中的前馈定时（本轮新调研，可迁移）

| 方法 | 出处 | 机制 | 对本项目的价值 |
|---|---|---|---|
| **Oerder–Meyr 数字滤波与平方定时恢复** | IEEE Trans. Commun., 1988 | 非线性变换（平方）产生码元速率谱线，FFT 直接读出定时相位与频偏，前馈、无环路 | 理论源头。LTC 每个位边界必有跳变 → 位时钟线极强，天然适合 |
| Gardner 定时误差检测 | IEEE Trans. Commun., 1986 | 每码元 2 采样的无数据 TED，`e[k]=x(kT+T/2)[x(kT)−x(kT+T)]` | 备选：每半比特 12 采样远超 2 采样要求，可用于数据辅助精调 |
| ML 前馈定时（最大输出能量准则） | 教科书级（Meyr/Moeneclaey/Fechtel "Digital Communication Receivers"） | 定时 = 使匹配滤波输出能量最大的偏移，NDA 情形闭式/搜索 | **本方案实际采用的准则**：半比特积分能量最大化 |
| RFID FM0/Miller 的 ML 序列检测 | IEEE TVT 等 2018–2025 多篇 | FM0 与双相空格同族，用序列级软判决代替逐比特硬判决 | 对应本方案的"期望值链式校验"（§3.4） |

FM0 = bi-phase space 的别名（EPC Gen2 称 FM0，SMPTE 称 biphase mark），即 LTC 的编码族。RFID 文献证实了该编码族做软判决序列检测是对的路线。

### 1.3 机器学习路线

LTC 是 80 位自同步码、每帧自带 16 位同步字、BCD 语法高度受限。NN 解码在信噪比与工程复杂度上都不划算（需要带 GPU 训练数据、模型体积与单文件 HTML 分发冲突），检索不到任何严肃成果。**不建议投入**。

## 2. 算法总览：分段前馈定时 + 匹配滤波软判决 + 期望值链式校验

```
带通(0.7·f_bit/2 ~ 1.3·f_bit, 385 taps 线性相位 FIR)      ← P1 的带通
  → 分段（1.5 s 窗、0.75 s 滑窗）
    → 定时估计：率搜索(±1%) × 相位搜索 = 使 Σ半比特能量 最大的 (rate, phase)
       —— 全程无判决参与，伪跳变不存在                 ← 这就是"前馈"
    → 锁相质量 = 半比特均值能量 / 带内总能量（周期信号 ~1.3，白噪 ~0.12，门限 0.4）
    → 匹配滤波软判决：x1,x2 = 两半格均值 → llr ∝ |x1−x2|−|x1+x2|（沿用现网正确的判决）
    → 对两个半比特相位类各解一遍（能量度量无法区分二者，见 §4.1）
    → 同步字：精确 16 位匹配 + LLR 相关备选
    → 期望值链式校验：静态 digit(hh/mm) 跨帧平均定死，逐帧核对 V0+k 的软代价
    → 段间聚类投票：最大簇 ≥4 且 ≥2×次大簇才允许输出            ← 零错锁闸门
```

与 PLL 原型（`bench-pll2.mjs`）的本质区别：**没有任何边沿检测**。PLL 原型仍以施密特跳变为环路牵引源，宽带噪声下伪跳变照进环路——这正是它白噪 0.15 封顶的原因；前馈方案的定时估计量是整段积分的能量，单点噪声淹没在积分里。

## 3. 实测

### 3.1 识别矩阵（6 s 文件，每行一次解码）

| 场景 | 现有实现(默认路径) | PLL 原型 | **前馈原型** |
|---|---|---|---|
| 干净 0.5 | ✅ | ✅ | ✅ |
| −30 dBFS 低电平 0.03 | ✅ | ✅ | ✅ |
| 白噪 0.15（−4.8 dB） | ✅ | ✅ | ✅ |
| **白噪 0.20（−7.3 dB）** | ❌ 门控拒 | ❌ | **✅（支持 4/7）** |
| 白噪 0.30（−10.8 dB） | ❌ | ❌ | ❌（正确地不猜） |
| 对白 0.10–0.50 | ❌ 门控拒 | ✅ | ✅ |
| **对白 0.80（−23.7 dB）** | ❌ | ✅ | **✅（支持 5/7）** |
| 50 Hz 工频堆叠 0.15 | ✅ | — | ✅ |
| 带限 400–3200 Hz | ✅ | — | ✅ |
| 软削波 | ✅ | — | ✅ |
| 时钟 +0.4% 变速 | ✅（误差 185 帧） | — | ✅（误差 0） |
| 1 秒信号丢失 | ✅ | — | ✅（与现网同语义：−25 帧） |
| −60 dBFS + 噪 0.02 | ❌ | — | ❌（正确地拒绝） |
| 纯噪 0.30 / 0.80 / 纯对白 | 正确拒绝 | 正确拒绝 | **正确拒绝** |
| **错锁 / 误锁** | 默认 0 / 兜底曾 65.8% | 0 | **0 / 0** |

### 3.2 错锁回归（模拟现网 P0 测试：8 种子 × 干扰矩阵）

| 套件 | 正确 | 错锁 | 无锁定 |
|---|---|---|---|
| 对白 0.25–0.60 + LTC 0.03 + 白噪 0.02（8 种子 × 7 电平 = 56） | 56 | **0** | 0 |
| 白噪 0.15–0.30 + LTC 0.05（8 种子 × 4 电平 = 32） | 18 | **0** | 14 |

白噪 0.25 档位的 14 次"无锁定"全部是**主动拒绝**（簇支持不足或优势比不够）——宁可不答也不猜错，与现网"低质量不给可写回数字"的原则一致。

### 3.3 性能

6 s 文件全解码 ~0.5 s（Node，单线程）。60 s 文件约 5 s，放 Blob Worker 可接受。带通 385 taps × 288 k 采样 ≈ 110M 乘加是主要开销，工程上可换 FFT 卷积或降到 193 taps（对白档无差别，白噪档待复测）。

### 3.4 对照结论

- **白噪门限 +2.5 dB（0.15→0.20）**：来自前馈定时，与文档 §5 的预言吻合（"彻底解决需要前馈定时"）。
- **对白门限维持 0.80**：带通仍是主要功臣，前馈方案与 PLL 方案同档。
- **零错锁**：双重机制——静态 digit 跨帧平均（杀掉小时位单帧误判的系统性传播）+ 簇优势比闸门（杀掉低支持假锁定）。

## 4. 开发中抓到的问题（集成 P2 时必须移植的经验）

### 4.1 半比特相位模糊（最重要）
双相标记码**每个位边界必有跳变** → 能量最大化度量在位栅格和"半比特错位栅格"上得分几乎相同（错位栅格上 x1、x2 恒反相，能量一样高）。**任何只靠能量的定时估计都无法区分二者。** 解法是两个相位类各解一遍、用同步字+链式校验裁决。PLL 原型没踩这个坑是因为跳变天然锚定位边界——前馈方案没有这个锚，必须用数据验证。

### 4.2 静态 BCD digit 的单帧软判决会系统性传播
`01:00:00:00` 的小时个位（bit 48）若单帧 llr 偏弱被判成 0，则 V0=50，后续"期望 V0+k"全部自洽（错误的小时值进入期望值，每帧代价仍低），形成稳定假链。修法：hh/mm digit 是段内常量，**跨 8 帧平均 LLR 后一次定死**；误差 1000 帧（ss 十位）的错锁案例同属此类。

### 4.3 "低支持小簇"放行 = 静默错锁
`win.arr.length ≥ 2` 时，2–3 个相邻重叠段可凭同一段局部干扰形成自洽假簇。闸门须要求 **≥4 支持且 ≥2×次大簇**。代价是高噪下主动不答（§3.2 的 14 次 no-lock），这正是产品要的行为。

### 4.4 分数帧取整伪影
中位数落在整数帧 −ε 时，`floor + 负小数` 会错出整整一帧（实测 −2.0 帧假错锁）。估计精度远低于帧分辨率时**先取整再换算**。

## 5. 与现有代码库的关系（建议路线）

本原型 = `docs/LTC识别强化方案.md` 路线图的 **P1+P2+P3 一体升级版**：

| 路线图项 | 本原型中的状态 |
|---|---|
| P1 带通前置 | 已实现（但门控本身也被本方案替代：锁相比值比"边沿计数门控"更物理） |
| P2 PLL 主路径 | 被前馈定时**取代**（PLL 降级为备选，不必再写） |
| P3 帧率前馈估计 | 定时搜索天然支持：对每个候选 fps 跑一遍、按锁相比值选 fps（原型固定 25 fps 未做，是工程接线而非算法工作） |
| P0 收紧验收 | 链式校验 + 静态 digit 平均 + 簇闸门已覆盖其意图，可直接替代兜底模式 |
| 文档 §8 建议的"错锁必须为 0"回归 | `bench-ff-wronglock.mjs` 即模板，可固化进 `test/` |

**集成注意**：`src/ltc-decoder.js` 与 `src/ltc-worker.js` 双份实现需同步改；`test/ltc-low-level.test.mjs` 的双侧一致性用例可直接当回归。原型 ~250 行核心代码，纯函数无依赖，可整体平移进 worker 字符串模板。

**保留现网硬路径作为快速通道是合理的**（干净信号上它更快、且已被 19 个用例钉死）；前馈路径作为"门控被拒/低质量时的主增强"，替代现在的兜底软同步。

## 6. 未覆盖 / 风险声明

- 全部合成信号；真实录音机的上升时间、codec 预处理未测（与上一阶段相同）。
- 只验证了 25 fps。23.976/29.97df/24/30 与 44.1/96 kHz 在算法上无特殊点（定时搜索率宽 ±1% 覆盖 ±0.4% 实测变速），但未实测。
- 变速只测恒定 +0.4%；连续变速靠分段估计天然支持，未实测。
- 多声道相位影响未测。
- 白噪 0.25 以上、对白 1.20 以上主动不答；若业务需要可再加数据辅助精调（Gardner TED 或期望值波形相关）把门限继续下压，但收益/复杂度比一般。
- "零错锁"是 88 次受控观测 + 16 场景矩阵的结论，不等于任意素材零风险——簇闸门与人工确认流程仍是最后防线。
