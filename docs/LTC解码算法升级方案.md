# LTC 解码升级方案（Robust Biphase + PLL）

## 目标

在不引入后端、神经网络模型或外部依赖的前提下，提高 SlateSync 对以下素材的容错能力：

- 录音机采样时钟与标称采样率存在缓慢漂移；
- LTC 边沿存在抖动、削波、瞬态点击和少量伪边沿；
- 低电平 LTC 已经经过分析副本增益，但边沿间隔不再完全规则；
- 主线程与 Worker 必须使用完全相同的判决逻辑。

## 当前实现

新增 `src/ltc-robust.js`，由主线程和 `LTC_WORKER_CODE` 共同调用。它替代原先固定阈值的 `decodeBits`，但保持原有返回结构，因此不会改变帧解析、DF/NDF、TimeReference 和 UI 数据层接口。

### 1. 边沿序列作为观测量

`findEdges` 先产生带亚采样交点的边沿位置。Robust decoder 不直接把每一个间隔硬编码成 1-bit 或 0-bit，而是为当前边沿生成候选：

- 单间隔候选：两个边沿之间约为 `2H`，判为 `0`；
- 双间隔候选：连续两个间隔各约为 `H`，判为 `1`；
- 合并候选：检测到一个明显短的伪边沿时，将两个间隔合并为一个 `0`，仅在总时长接近 `H` 时启用。

这里 `H` 是半 bit 样本数。

### 2. 对数 timing cost

候选代价使用 `abs(log(observed / expected))`，比绝对误差更适合处理不同帧率和不同采样率。额外加入：

- 远离标称时长的惩罚；
- 双边沿不对称惩罚；
- 明显不确定候选的拒绝，而不是强行吞掉伪边沿。

### 3. 慢速 PLL

每个已接受的 half-bit 只以小步长更新本地时钟，并限制在标称值 ±16% 内：

```text
H[n+1] = H[n] + 0.035 * clamp(observed - H[n], ±0.16 * H0)
```

因此可以追踪录音设备的慢时钟漂移，同时避免单个异常边沿把后续 80-bit 帧全部带偏。

### 4. 诊断保持兼容

返回的 `trackedHalfBitSamples`、`observedHalfBitSamples`、`observedJitter` 和 `rejected` 仍然供原有质量评分使用。也就是说，算法增强不会把“能解码”误认为“高质量”：漂移和异常边沿仍会进入质量分级与人工复核提示。

## 为什么这比本地旧算法更强

旧判决是固定区间：`0.55..1.45H`、`1.45..2.7H`，并且优先尝试 `1`。这在干净 LTC 上有效，但遇到漂移或伪边沿时容易发生 bit slip。新判决具备：

1. **时钟跟踪**：不要求整段音频的 H 恒定；
2. **候选竞争**：对 0/1 两种解释计算代价，而非单一 if/else；
3. **伪边沿防护**：异常间隔可以被拒绝或有限合并；
4. **Worker 一致性**：主线程和 Worker 注入同一个函数实现，避免两条路径结果不一致；
5. **低风险集成**：帧同步字、BCD 合法性、连续帧锁定、DF/NDF 和最终置信度仍由原有解码器负责。

## 验证方式

现有测试覆盖：

- PCM16、Float32、低电平和近量化噪声 LTC；
- 24/23.976/29.97 DF；
- 延迟出现、尾段出现、削波、DC 偏置；
- 静音、语音、噪声和正弦波误检防护；
- 主线程/Worker 结果一致性；
- BWF、iXML、Poly WAV 和 Resolve 输出兼容性。

建议下一阶段补充真实录音回归集，并为每条样本记录：`sampleRate`、标称 FPS、实际起始 TC、SNR、漂移 ppm、削波比例、边沿抖动、误锁率和解码耗时。只有在真实素材集上完成对照，才能严谨宣称“超越 SOTA”。

## 下一阶段（建议）

1. **全局帧级 Viterbi/beam search**：在 80-bit 帧候选之间联合优化，而不是只在边沿级贪心；
2. **二阶 PLL**：同时估计 `H` 和 drift rate，处理长文件的线性时钟偏差；
3. **多声道证据融合**：相同 take 的 LTC 声道联合投票，保留每个声道的独立诊断；
4. **可复现 benchmark**：合成信号 + 真实现场录音，按噪声、漂移、失真、断续和串音分层；
5. **可选模型化前端**：仅作为候选边沿/置信度建议器，最终仍由确定性的 SMPTE LTC 语义校验拦截误检。
