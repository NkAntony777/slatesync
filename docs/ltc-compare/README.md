# LTC 解码算法对比基准（基线 A：分段前馈定时）

> 本文档是**算法对比的规格书**。任何新算法必须与基线 A 跑**完全相同的评测协议**，
> 报告同一组指标，否则比较无效。
> 基线 A 的完整调研报告见 `../LTC前馈定时方案.md`；上游背景（现网实现结构、
> PLL 原型、P0–P4 路线）见 `../LTC识别强化方案.md`。
> 环境：Node ≥ 24，无第三方依赖，无需 `npm install`。

## 0. 给对比者的快速开始

```bash
# 复现基线成绩（约 15 s + 90 s）
node docs/ltc-compare/bench-ff.mjs
node docs/ltc-compare/bench-ff-wronglock.mjs
```

接入你自己的算法（见 §4 的接口约定）：

1. 在 `docs/ltc-compare/` 下新建 `your-decoder.mjs`，导出一个
   `decodeFile(Float32Array 数据, number fps) → { timeRef: bigint, support: number, total: number } | null`；
2. 复制 `bench-ff.mjs` / `bench-ff-wronglock.mjs`，把 import 换成你的模块；
3. 跑通后把成绩填进 §5 的对比表，**不得修改场景生成参数与通过标准**。

**对比的第一指标是错锁数（必须为 0），第二指标是识别矩阵通过数，第三指标是运行时。**
"宁可不答也不猜错"是本项目的硬性产品约束：高噪场景主动 no-lock 优于给出错误数字。

## 1. 基线 A 算法规格（可复现级）

### 1.1 总流水线

```
输入 Float32Array（单声道 PCM）+ 标称 fps
 1. 带通 FIR：385 taps（奇数），Hamming 窗，线性相位
    通带 [0.7·f_bit/2, min(1.3·f_bit, 0.45·fs)]，f_bit = 80×fps
    （25 fps / 48 kHz → 875–3250 Hz）。系数按 Σh 归一化，群延迟 mid = (N-1)/2
 2. 前缀和 P[n] = Σx，半格均值用前缀差分 O(1) 取得
 3. 分段：窗长 1.5 s，滑窗 0.75 s（50% 重叠）
 4. 每段定时估计（前馈，无判决参与）：
    a. 率搜索：half = half0·(1 + ri·0.001)，ri ∈ [-10, 10]（half0 = fs/(fps·160)）
    b. 相位搜索：每率 8 个相位（均匀覆盖一个位周期），
       度量 metric1 = Σ(半格1均值² + 半格2均值²)，积分窗两侧各留 g=0.16 保护带
    c. 取 metric1 最大的 (rate, phase)；该度量有位周期级的半比特模糊（见 §1.3-A），
       相位精调改用度量 metric2 = Σ(|x1−x2| − |x1+x2|)²，g=0.18，两遍 ±T/16 步进
 5. 锁相比值 lockRatio = metric1·span / (Σx²·cells·2)；< 0.4 判该段无信号
    （周期信号实测 ~1.3，白噪 ~0.12，分离度巨大）
 6. 双相位类解调：对相位类 0 和半比特错位各做一次：
    x1 = 前半格均值，x2 = 后半格均值（g=0.18 保护带）
    llr = (|x1−x2| − |x1+x2|) / (|x1|+|x2|+1e-12)，bit = llr > 0
 7. 帧同步：对每个相位类，扫所有 80 位窗口：
    精确匹配 16 位同步字（0x3FFD / 反极性 0xBFFD 两种极性）→ hard
    或 |LLR 相关|/16 ≥ 0.62 → soft；按 (hard, |corr|) 排序取 top 24
 8. 期望值链式校验（每个候选同步位置）：
    a. 静态 digit（hh/mm 共 16 bit）跨 F = min(可用帧数, 8) 帧平均 LLR 后
       软解码（逐 digit 在合法范围内取代价最小的值），staticCost ≤ 1.2 才继续
    b. 首帧动态 digit（ss/ff）单帧软解码 → V0；非法 BCD 则弃
    c. 逐帧 k=1.. 计算"期望值 V0+k 的软代价"（仅 ss/ff 6 个 digit，26 bit；
       错 1 bit 累计 |llr| ≤ 1.5 记 good），good ≥ 5 且可用帧数 ≥ 6 才通过
 9. 候选打分：score = good·2 + hard·8 + |corr|·6 − staticCost；每段取最高分
10. 段间聚类：把每段的 fileStartFrame = V0 − 帧0采样位置/spf 按四舍五入聚类；
    最大簇须 ≥ 4 段 且 ≥ 2×次大簇，否则整文件不答
11. 输出：timeRef = framesToSamples(整数化后的中位帧)，support/total 报告段支持度
```

### 1.3 关键设计决策（对比者请阅读，避免重蹈覆辙）

**A. 半比特相位模糊（本算法最重要的坑）。** 双相标记码每个位边界必有跳变，
所以"半比特错位栅格"上两半格恒反相，能量度量 metric1 在两个相位类上得分几乎
相同——**任何纯能量定时估计都无法区分二者**。metric2 有分辨力但高噪下也会选错。
解法：两个相位类各完整解一遍，由同步字 + 链式校验裁决。

**B. 静态 BCD digit 跨帧平均。** hh/mm 在段内是常量。若单帧软判决把小时个位
判错（边际 bit），V0 错 100 帧量级，且后续"期望 V0+k"自洽（错误值进入期望值），
形成系统性假链——实测会让 3-7 个段全部一致地报同一个错值。跨 8 帧平均 LLR
后一次定死可根除。

**C. 簇闸门 = 零错锁的来源。** 曾用 `≥2 支持` 放行，结果白噪 0.25 下 2-3 个相邻
重叠段靠局部干扰形成自洽假簇（误差恰好 1000 帧 = ss 十位）。闸门要求 ≥4 支持
且 ≥2×次大簇后，88 次回归零错锁。代价是高噪下主动不答。

**D. 分数帧取整伪影。** 中位数在整数帧 −ε 处时 `floor + 负小数` 会错整整一帧
（实测 −2.0 帧假错锁）。先取整再换算。

**E. "读不出"优于"读错"。** 曾把链代价门限从 1.5 放松到 2.0 试图吃到白噪 0.30，
立刻出现 180000 帧的错锁。1.5 以上的余度都是错锁空间，不要拿它换识别率。

### 1.4 已知失败模式与边界

| 边界 | 行为 | 说明 |
|---|---|---|
| 白噪 ≥0.30（−10.8 dB）/ 对白 ≥1.20 | no-lock | 主动放弃，非误拒 |
| −60 dBFS LTC + 噪 0.02 | no-lock | 带内 SNR 过低，物理极限 |
| 变速 | 每段独立定时估计，天然支持 | 只实测恒定 +0.4% |
| 信号丢失 | 丢失段 noSignal，其余段正常 | 1 s 丢失实测通过 |
| 帧率未知 | 算法对每个候选 fps 各跑一遍取 lockRatio 最大 | 原型固定 25 fps 未实测 |
| 真实素材 | 未测 | 全部结论基于合成信号 |

## 2. 评测协议（所有算法必须一致）

### 2.1 识别矩阵（bench-ff.mjs）

信号源：`test/ltc-encode.mjs` 的 `encodeLtcAudio`（理想方波，位边界跳变，25 fps，
起始 TC `01:00:00:00`）与 `encodeVoiceLike`（3.7 Hz 音节门 × [0.5 均匀噪 + 0.3·sin137Hz
+ 0.2·sin311Hz]，固定种子 12345）。LCG 白噪 `rng(seed)`。全部 48 kHz / 6 s / 单声道。

| # | 场景 | 生成参数 | 通过标准 |
|---|---|---|---|
| 1 | 干净 0.5 | amp 0.5 | err ≤ 1 帧 |
| 2 | 低电平 | amp 0.03（−30 dBFS） | err ≤ 1 帧 |
| 3-11 | LTC 0.05 + 白噪 a | a ∈ {0.05…2.00}（9 档，seed 13） | err ≤ 1 帧 |
| 12-17 | LTC 0.03 + 对白 a | a ∈ {0.10…1.20}（6 档） | err ≤ 1 帧 |
| 18 | 50 Hz 工频堆叠 | 0.15·(sin50 + 0.5sin100 + 0.3sin150)/1.8 叠 LTC 0.05 | err ≤ 1 帧 |
| 19 | 带限 400–3200 Hz | LTC 0.10 过一阶 HP400 + LP3200 | err ≤ 1 帧 |
| 20 | 软削波 | LTC 0.9 → tanh(2.2x)/tanh(2.2) | err ≤ 1 帧 |
| 21 | 变速 +0.4% | fps=25.1，nominalFps=25，amp 0.10 | err ≤ 1 帧 |
| 22 | 1 s 丢失 | startDelay 1 s + 静音 2-3 s 段，amp 0.10 | err ≤ 1 帧（期望值 89975 帧，见下） |
| 23 | −60 dBFS | LTC 0.001 + 白噪 0.02（seed 23） | **必须拒绝** |
| 24-26 | 纯噪 0.30 / 纯噪 0.80 / 纯对白 0.30 | seed 7 / 31 / voice | **必须拒绝**（no-lock 或 best===null） |

err 定义：`Number(timeRef − EXPECTED)/1920`，EXPECTED = `01:00:00:00` 的采样数
= 172800000。注意场景 22：LTC 物理起点在采样 48000，外推到文件起点应为
89975 帧（脚本内 `EXPECT_OVERRIDE` 已按现网解码器同语义处理，**勿改**）。

### 2.2 错锁回归（bench-ff-wronglock.mjs）

| 套件 | 构成 | 通过标准 |
|---|---|---|
| 对白 | 8 种子 × 7 电平 {0.25…0.60}，LTC 0.03 + voice + 0.02·sin 种子噪 | **WRONG = 0** |
| 白噪 | 8 种子 × 4 电平 {0.15…0.30}，LTC 0.05 + LCG 白噪 | **WRONG = 0** |

WRONG = 锁定但 err > 1 帧。no-lock 不计错（主动放弃合法），但会进第三指标。

### 2.3 报告格式

```
识别矩阵: right=N/23  WRONG=M  false-lock=K  no-lock=J
错锁回归: voice ok=? WRONG=? no-lock=?  /  white ok=? WRONG=? no-lock=?
单次解码耗时（6 s 文件，Node 单线程）
```

## 4. 算法接口约定（新算法必须实现）

```js
// docs/ltc-compare/your-decoder.mjs
export function decodeFile(data /* Float32Array */, fpsNDF /* number, e.g. 25 */) {
  // 返回 null 表示"不答"（合法且被鼓励）；返回：
  return {
    timeRef: bigint,      // 文件采样 0 处的外推 TimeReference（与 framesToSamples 同语义）
    support: number,      // 支持锁定的段/窗数（自有定义，报告用）
    total: number,        // 总段/窗数
  };
}
```

约束：单次调用完成整文件解码；不得读文件系统；不得要求 GPU/原生模块
（产品形态是单文件 HTML + Blob Worker）；允许任意预处理（带通、重采样、
机器学习推理皆可），但需在文档中声明。
